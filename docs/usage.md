# 局域网排查与数据说明

## 学生打不开页面

1. 确认教师端「邀请学生」显示服务正在运行，并将完整访问地址（包含端口）填入学生浏览器。教师管理地址使用教师电脑的回环网卡，学生使用邀请弹窗中的局域网地址。
2. 确认师生设备在可互访的局域网中，避免使用开启客户端隔离的访客 Wi-Fi。校园网络若跨 VLAN，可请管理员确认师生设备之间能访问填写的 TCP 端口。
3. 有多个网卡时，优先选择当前教室的 Wi-Fi 或有线网卡。VPN 和虚拟网卡可能同时出现在列表中。Wi-Fi 重新连接而 IPv4 变化时，用「切换网卡」重新绑定并分享新地址。
4. Windows 如显示防火墙询问，在可信教室网络上允许 ClassRelay 在专用网络接收入站连接。管理端只绑定 `127.0.0.1`，学生访问端默认使用 TCP 17887。
5. 端口占用时，用 `-student-port 17897` 或 `-teacher-port 17898` 启动。学生端监听失败会显示在邀请弹窗中，教师端监听失败会显示在终端。
6. 若教师代理软件拦截了回环或局域网地址，让浏览器绕过这些地址的代理。局域网地址使用 `http://`。

## 消息与权限

- 教师端用当次启动的一次性令牌交换 HttpOnly 会话 Cookie。程序重启后用新链接登录。学生会话凭证仅以散列存入 SQLite。
- 教师和学生接口分开监听。写操作校验请求来源，消息发送者由服务端会话决定。移除学生会撤销课堂历史和发送权限；教师保留该学生的既往私聊记录。
- 消息限制为 UTF-8 64 KiB。服务端先保存消息和接收名单，再用 SSE 通知客户端读取。断线重连按 SQLite 递增游标取回遗漏的消息，使用相同请求编号重试不会重复入库。
- 保存后显示「已发送」，接收方确认后显示「已送达」。教师查看当前私聊底部时更新教师侧的未读数。学生的送达确认仅代表接收，阅读状态单独处理。
- 历史按每页 40 条加载。点「查看更早的消息」读取旧记录。当前标签页保留未发送草稿和失败重试项，成功保存的消息可在关闭网页或重启后恢复。
- 目标浏览器为 Chrome / Edge 111+、Firefox 128+ 和 Safari 16.4+。局域网 HTTP 上复制按钮会尝试浏览器的兼容复制机制，失败时可以直接选择消息内容。

## 备份与清空

数据文件为 `classrelay.sqlite`。默认目录是 macOS 的 `~/Library/Application Support/ClassRelay`、Windows 的 `%APPDATA%\ClassRelay`、Linux 的 `${XDG_CONFIG_HOME:-~/.config}/ClassRelay`。可用 `-data-dir` 调整目录。备份或恢复前先退出程序，然后复制整个数据目录。

「课堂设置 → 清空历史消息」会要求再次确认。确认后会删除所有人的历史消息及送达记录，并保留课堂设置和学生会话。课堂记录如需备份，请在清空前保存副本。
